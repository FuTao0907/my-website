### v1.3 线上登录验证受阻：GitHub OAuth 账号级风控（确诊）+ A2 方案定案

**线上登录验证过程（用户已创建 OAuth App、配置 CF 环境变量、提供 PAT）**：

- **首轮 OAuth 登录失败 404** → 排除法诊断：本机 curl 302 正常、web_fetch 200 正常、无痕窗口（无 cookie）302 正常 → 确认**已登录 GitHub 会话访问 authorize 必 404**（无痕登录 GitHub 后复现）→ **GitHub 账号级风控**（GitHub 侧限制，非本站配置）。
- **切换 `auth_type: implicit`（PAT 隐式模式）** 部署验证：本地 preview 与线上均仍显示 "Login with GitHub"；查 bundle 确认 Decap 3.16 无 PAT 输入界面、implicit 仍走 authorize（`response_type=token`）→ **Decap 所有登录路线均被风控卡死**。
- **用户提供的 fine-grained PAT 验证有效**：`/user` 返回 FuTao0907/明；repo 读写权限均 True；根目录读取正常（`src/content/notes` 404 仅为目录不存在）。

**决策（用户选 C）**：先自写轻量 CMS 用起来，Decap 保留待风控解除。
**A2 方案**：GitHub PAT 只存 Cloudflare 环境变量，浏览器不接触 token；`/manage` 静态管理页 → `/api/cms/*`（Pages Functions 代理）→ GitHub Contents API → 自动部署。
**方案文档**：`docs/prd/v1.3/cms-a2-plan.md`（架构/接口/前端/集合映射/CF 配置/实施步骤/风险）。
