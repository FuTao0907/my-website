# Ange's website · 开发规范

> 本文件是开发过程中的**硬性规则**，与 `prd/v1.0/PRODUCT_PRD.md`（产品需求，已冻结）配套使用。
> PRD 管"做什么"，本文件管"怎么做、怎么发版、怎么记问题"。

---

## 1. 版本号规则（语义化版本 SemVer）

格式：`MAJOR.MINOR.PATCH`，初始版本 **0.0.1**。

| 位 | 何时 +1 | 例子 |
|----|---------|------|
| **MAJOR（主版本）** | 整个框架/架构发生改变，不兼容旧版本 | 0.0.1 → 1.0.0（v1 全部完成）；1.0.0 → 2.0.0（框架重写） |
| **MINOR（次版本）** | 新增了功能，向后兼容 | 1.0.0 → 1.1.0（加了一闪念）、1.1.0 → 1.2.0 |
| **PATCH（修订号）** | 修了问题，不新增功能 | 1.0.0 → 1.0.1 |

**具体约定**：
- 项目初始化、第一次能跑：**0.0.1**
- v1.0 全部功能做完、正式上线：**1.0.0**
- 之后每加一个功能模块：MINOR +1
- 之后修一个 bug：PATCH +1
- 只有框架级重构/迁移才动 MAJOR

版本号记录在 `package.json` 的 `version` 字段，同时在 `docs/CHANGELOG.md` 里记录每次发版内容。

## 2. 问题记录规则（不许同一个问题修第二次）

**原则**：问题只出现一次。同一个问题不能修第二遍。

### 2.1 遇到问题时必须做的事

在 `docs/ISSUES_LOG.md` 里追加一条记录，格式：

```markdown
### ISSUE-XXX：一句话标题
- **日期**：YYYY-MM-DD
- **现象**：用户看到/报错是什么
- **根因**：为什么会出现（技术原因）
- **解决方案**：最终怎么修的（具体操作/配置/代码改动）
- **状态**：已解决 / 已绕开（用了替代方案）
- **备注**：后续如何避免再踩
```

### 2.2 卡住了怎么办

- 同一个问题**尝试 2 次仍失败**，不要再死磕
- 换思路：用**替代方案**绕过（记录为"已绕开"状态）
- 替代方案也要写进 `docs/ISSUES_LOG.md`，说明为什么不用原方案、替代方案是什么
- 绝对禁止：同一处问题反复改、反复试、不记录就继续

## 3. 工程规范

- **包管理器**：统一用 **Yarn**（见全局 AGENTS.md）。依赖写进 `package.json`，禁止混用 npm/pnpm
- **提交信息**：Conventional Commits（`feat:` / `fix:` / `chore:` / `docs:`）
- **分支**：`main` 保持可上线；功能在 feature 分支做，合并回 main
- **样式**：Tailwind CSS v4，不写零散全局 CSS
- **提交前自检**：本地 `yarn build` 能过、`yarn preview` 打开无报错
