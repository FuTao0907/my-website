## 一、v1.2 要解决的问题（从用户反馈提炼）

> 用户原话："这个网站不成熟，哪怕是一个最基础的功能 demo 网页，我都知道这个功能是做什么的、逻辑是完善的。当前项目给不了我这种感觉 —— 一个模块，我能列出一个思维导图，其中模块的某一个部分会有哪些效果，如果没有达成某种条件又应该是什么效果。"

提炼为三个核心问题：

### 问题 1：状态不完备（"不成熟感" 的根因）



* **现象：** 每个模块只有 "正常有数据" 这一种状态。用户无法预判：没有数据时、加载中时、失败时，界面应该长什么样

* **本质：** 缺少**空状态 / 加载状态 / 错误状态**三类边界状态的明确设计与实现

* **为什么没做到：** 开发期内容库里一直有示例数据（hello-world、example 等），所有页面都有内容可显示，边界状态从未被触发，因此从未被设计

### 问题 2：加载体验差（最首要，用户明确要求）



* **现象：** 切换页面不是立即切换，要等约 1 秒，能感觉到 "在加载"

* **技术原因：** Astro View Transitions 默认**等待新页面 HTML 完全下载完成后才开始过渡动画**；国内网络访问下这一步耗时约 1 秒。等待期间无任何加载提示 → 用户不知道是 "在加载" 还是 "卡了"

* **为什么没做到：** v1.0 PRD 锁定 "极简单色、动效克制、无设计交互动画"，加载动画在初始范围外

### 问题 3：交互动画与反馈缺失



* **现象：** 交互只有 hover 变色，没有按压反馈、没有操作结果提示（除复制成功外）

* **本质：** 缺少统一的**反馈机制**（点击态、toast、焦点态）

* **为什么没做到：** 同上，v1.0/v1.1 未把 "设计交互动画" 纳入范围

## 三、v1.2 候选功能清单（按优先级）

> 以下按优先级分组，请用户勾选哪些做、哪些不做。

### P0 — 加载体验（用户指定最首要）

#### 1. 页面切换加载动画



* **目标：** 切换页面时不再 "无反馈等待 1 秒"

* **方案 A：顶部进度条**（仿 GitHub/NProgress）


  * 点击链接 → 顶部出现细进度条动画（400ms 内到 90%）→ 新页 ready 后补满 100% 并淡出

  * 优点：实现简单、反馈明确、不改变现有过渡

* **方案 B：立即离开动画**


  * 点击链接 → 旧页立即淡出 → 新页加载完成后淡入（不等新页 ready）

  * 优点：切换感知最快；缺点：若新页加载慢会出现短暂空白

* **方案 C：A + B 结合**（推荐）：离开动画 + 进度条兜底

* **验收：** 国内网络下切换页面，500ms 内必有视觉反馈；无白屏卡顿感

* **是否做：** ✅

#### 2. 链接预取（Prefetch）



* **说明：** 开启 Astro 内置 prefetch（链接进入视口 /hover 时预取新页 HTML），切换时新页已就绪，等待感趋近 0

* **工作量：** 极低（配置项 + 按需微调）

* **验收：** hover 导航链接后，点击切换 < 300ms 出内容

* **是否做：** ✅

#### 3. 图片加载占位（LQIP）



* **说明：** 博客 / 收藏封面图懒加载时显示模糊占位或几何占位，避免图片区域空白闪跳

* **工作量：** 低

* **是否做：** ✅

### P1 — 状态完备性（"思维导图" 补全，问题 1 的解决方案）

> 目标：全站每个内容模块都具备完整的
>
> **状态思维导图**
>
> ：正常态 / 空态 / 加载态 / 错误态

#### 4. 全局空状态组件



* **说明：** 统一空状态样式（图标 + 一句话文案 + 建议操作 CTA），覆盖：


  * 博客列表（暂无文章）、标签页（该标签暂无文章）

  * 项目列表（暂无项目）、项目筛选后无结果

  * 收藏各品类（暂无收藏）

  * 一闪念（暂无内容）

  * 搜索页（无搜索结果 → "换个关键词试试"）

* **验收：** 删除某模块全部内容后，页面显示友好空态而非空白 / 报错

* **是否做：** ✅

#### 5. 搜索加载状态



* **说明：** 搜索输入时显示 "搜索中…"；结果返回后显示 "共 N 条结果"；无结果显示空状态

* **是否做：** ✅

#### 6. 错误状态处理



* **说明：** 非 404 的加载失败（网络错误 / 资源缺失）显示友好错误页：文案 + 重试按钮 + 回首页

* **是否做：** ✅

#### 7. 筛选 / 分页边界



* **说明：** 项目技术栈筛选、博客分类 Tab 无结果时显示空态 + "清除筛选" 入口

* **是否做：** ✅

### P2 — 交互反馈闭环（问题 3 的解决方案）

#### 8. 统一按压反馈



* **说明：** 按钮 / 卡片 / 链接增加 active 态（按下时轻微缩放或颜色加深），全站统一（`active:scale-[0.98]` 等）

* **是否做：** ✅

#### 9. 统一提示机制（Toast）



* **说明：** 轻量 toast 组件（右下角浮出、自动消失、可堆叠），统一承载：复制成功 / 失败、操作完成等状态消息（替换现有零散提示）

* **是否做：** ✅

#### 10. 键盘焦点态强化



* **说明：** 全站统一 `focus-visible` 高亮（外圈 accent 描边），键盘导航时清晰可见（a11y）

* **是否做：** ✅

#### 11. 触摸目标规范



* **说明：** 移动端交互元素最小 44×44px（导航汉堡菜单项、筛选 chips、图标按钮），避免误触

* **是否做：** ✅

### P3 — 一致性修补

#### 12. 详情页排版统一



* **说明：** 博客 / 项目 / 收藏详情页的元信息区（日期 / 标签 / 评分等）、标题、正文排版模式统一为同一套规范

* **是否做：** ✅

#### 13. 列表交互统一



* **说明：** 各列表页卡片 hover/active/ 箭头提示统一（同一套 class 模式），消除 "每个列表长得不一样" 的观感

* **是否做：** ✅

#### 14. 示例内容处理



* **说明：** 现有示例内容（hello-world、example 等）在真实内容补齐后清理或保留为演示数据（由用户决定）

* **是否做：** ✅
